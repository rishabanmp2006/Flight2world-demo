# Data and model weights

Nothing under `data/` or `models/` is in git. The original working copy held about 62 GB of data,
but almost all of it was **generated** — OpenDroneMap projects, prepared keyframes, run reports.
The **downloaded** inputs the pipeline needs come to about 6 GB.

`download_data.py` fetches exactly those inputs. The Zurich and UAVScenes archives are 28 GB and
33 GB; the script reads each zip's index over HTTP range requests and pulls out only the files the
pipeline uses, so you never download the whole archive. Re-running skips files already present at
the right size, so an interrupted download can simply be restarted.

```bash
cd sih3d_pipeline
.venv/bin/python download_data.py --list                  # what each target fetches
.venv/bin/python download_data.py models osm aukerman     # weights + the smallest dataset
.venv/bin/python download_data.py all                     # everything, ~6.2 GB
```

> [!IMPORTANT]
> **Several of these datasets are non-commercial, and YOLO11 is AGPL-3.0.** They are fine for
> research and for SIH, but not for a commercial deployment without permission from their authors.
> Licences and required citations are listed per dataset below.

## What gets downloaded

| Target | Lands in | On disk | Licence | Role |
|---|---|---|---|---|
| `models` | `models/` | ~0.3 GB | see [Model weights](#model-weights) | AI masks, scene labels, gap filling |
| `osm` | `data/ground_truth/` | < 1 MB | ODbL | Building outlines to check Aukerman measurements |
| `aukerman` | `data/odm_aukerman_baseline/` | ~0.5 GB | CC0 1.0 | First end-to-end run; smallest set |
| `semcity` | `data/semcitylocked/` | ~1.0 GB | CC BY-NC 4.0 | **Metric-accuracy test** (RTK GPS + official building models) |
| `agz` | `data/agz_zurich_seg59001/` | ~1.1 GB | academic research | Real 30 fps video-rate flight, facades |
| `zurich-gt` | `data/ground_truth/zurich/` | ~1.2 GB | swisstopo free geodata | Independent LiDAR + buildings for AGZ |
| `uavscenes` | `data/uavscenes_amtown03/` | ~2.1 GB | CC BY-NC-SA 4.0 | Primary development set |

**Disk budget.** The downloads are the small part. Each OpenDroneMap reconstruction writes its own
project folder, and those are large: in the original working copy a 100-second Zurich run took
0.2–1.7 GB, the Aukerman project 8.2 GB, SemCity 5.9 GB, and one full-quality run 36 GB. Keep at least
60 GB free if you intend to reproduce all the benchmarks.

## Aukerman — OpenDroneMap sample

77 nadir photos with EXIF GPS over Aukerman park, Ohio. A grid survey rather than a single pass, and
with no independent ground truth, but it is small and reconstructs reliably — the right first run.

- **Source:** https://github.com/OpenDroneMap/odm_data_aukerman
- **Licence:** CC0 1.0 (public domain dedication)

```bash
curl -L -o aukerman.zip https://github.com/OpenDroneMap/odm_data_aukerman/archive/refs/heads/master.zip

# -> data/odm_aukerman_baseline/odm_data_aukerman-master/images/  (77 photos)
```

## SemCityLockeD — metric-accuracy test set

170 consecutive nadir photos over the TU Munich city campus, taken from a DJI Matrice 350 RTK at
about 75 m. The images carry **RTK-grade GPS** in their XMP metadata (around 1–3 cm), and the site is
covered by **official LoD1/LoD2 building models** — which makes this the one set where building
dimensions on the reconstruction can be checked against an independent reference.

- **Homepage:** https://albertchen98.github.io/SemCityLoc
- **Data:** https://huggingface.co/datasets/DevinEaston/SemCityLockeD
- **Licence:** **CC BY-NC 4.0 — non-commercial only**, attribution required
- **Building models:** derived from Bavarian open government data (Bayerische Vermessungsverwaltung,
  CC BY 4.0) — attribute them when publishing results
- **Citation:** cite the SemCityLoc work as given on its homepage

**What the target fetches:**

- `original_images/` — the 170-frame continuous run, `DJI_20241217084340_0034_D.JPG` through
  `DJI_20241217084919_0203_D.JPG` (5280×3956). The dataset holds 962 images; these are the
  longest gap-free run.
- `LoD_model/TUM_CC_lod1.obj`, `LoD_model/TUM_CC_lod2.obj`
- `LoD_model/semantic_obj/TUM_CC_lod2_{GroundSurface,RoofSurface,WallSurface}.obj`
- The 108 MB LoD3 model only with `--with-lod3`

Every file is fetched from `https://huggingface.co/datasets/DevinEaston/SemCityLockeD/resolve/main/<path>`,
with no login required.

**Caveats.** These are still photos at about 0.5 fps, not video. The LoD models are exported in an
undocumented local frame, so `scripts/compare_lod.py` aligns the reconstruction to them with a rigid
2D transform (rotation and translation) and never fits scale — any remaining size difference is the
reconstruction's own metric error.

## UAVScenes AMtown03 — primary development set

One continuous planned flight over a town in Armenia: 1,120 nadir frames (2448×2048, about 2 fps)
from a DJI M300 RTK at about 80 m, with RTK GPS at 5 Hz, per-frame poses and intrinsics, and a
georeferenced reference mesh.

- **Homepage:** https://github.com/sijieaaa/UAVScenes · parent dataset https://mars.hku.hk/dataset.html
- **Data:** https://huggingface.co/datasets/sijieaaa/UAVScenes
- **Licence:** **CC BY-NC-SA 4.0 — academic and non-commercial use only**
- **Citations (required by the authors):**
  - Wang, S. et al., *"UAVScenes: A Multi-Modal Dataset for UAVs"*, ICCV 2025.
  - Li, H. et al., *"MARS-LVIG dataset: A multi-sensor aerial robots SLAM dataset for
    LiDAR-visual-inertial-GNSS fusion"*, International Journal of Robotics Research, 2024.

**What the target fetches**, without downloading the archives whole:

| From | Members | Size |
|---|---|---|
| `interval5_CAM_LIDAR.zip` (26.7 GB) | `interval5_AMtown03/interval5_CAM/*.jpg` — all 1,120 frames | 0.96 GB |
| | `rtk_positions_raw.csv`, `sampleinfos_interpolated.json`, two trajectory plots | small |
| | `interval5_LIDAR/*.txt` — every 10th scan, 112 of 1,120 | 0.08 GB |
| `terra_3dmap_pointcloud_mesh.zip` (6.3 GB) | `AMtown/Mesh.ply`, `AMtown/terra_ply/metadata.xml` | 1.01 GB |

The LiDAR subset is the 10th, 20th, 30th… scan, matching the original working copy.
`--lidar-every N` changes the spacing; `--lidar-every 1` keeps all 1,120.

Manual equivalent, if you would rather download the full archives (~33 GB):

```bash
curl -LO https://huggingface.co/datasets/sijieaaa/UAVScenes/resolve/main/interval5_CAM_LIDAR.zip
curl -LO https://huggingface.co/datasets/sijieaaa/UAVScenes/resolve/main/terra_3dmap_pointcloud_mesh.zip
mkdir -p data/uavscenes_amtown03/reference_mesh
unzip -q interval5_CAM_LIDAR.zip 'interval5_CAM_LIDAR/interval5_AMtown03/*' -d /tmp/uav \
  && mv /tmp/uav/interval5_CAM_LIDAR/interval5_AMtown03 data/uavscenes_amtown03/
unzip -q terra_3dmap_pointcloud_mesh.zip 'terra_3dmap_pointcloud_mesh/AMtown/Mesh.ply' \
  'terra_3dmap_pointcloud_mesh/AMtown/terra_ply/metadata.xml' -d /tmp/uav \
  && mv /tmp/uav/terra_3dmap_pointcloud_mesh/AMtown data/uavscenes_amtown03/reference_mesh/
```

(This keeps all 1,120 LiDAR scans, where the script keeps 112.)

**Caveats.** These are frames, not video, and there is no `.SRT` — the timestamps in the file names
sync with the RTK CSV. The camera looks straight down, so facades are barely visible. The reference
mesh is DJI Terra photogrammetry built from the same imagery, so it is **not** independent survey
truth; the LiDAR scans are a loose independent check.

## Zurich AGZ — real video-rate flight

A continuous 30 fps, 100-second, low-altitude flight down a Zurich street: frames 59001–62000
(1920×1080) from a GoPro Hero 4 on a tethered quadrotor, with oblique views of building facades.
This is the set closest to real SIH26158 input.

- **Homepage:** https://rpg.ifi.uzh.ch/zurichmavdataset.html
- **Archive:** https://download.ifi.uzh.ch/rpg/AGZ_data/AGZ.zip (27.8 GB)
- **Licence:** the dataset page releases it "with no restriction ... research, evaluation, and commercial
  purposes"; the readme inside the archive says the images are property of the authors and "can be
  used for academic research without any limitations". Treat it as free for research; commercial reuse
  of the images is unclear.
- **Citation (requested):** A. L. Majdik, C. Till, D. Scaramuzza, *"The Zurich urban micro aerial vehicle
  dataset"*, International Journal of Robotics Research 36(3), 2017.

**What the target fetches** — about 1.1 GB, out of the 27.8 GB archive:

```
MAV Images/59001.jpg … 62000.jpg    3,000 consecutive frames
Log Files/                          OnboardGPS, OnboardPose, BarometricPressure, RawAccel, RawGyro,
                                    GroundTruthAGL, GroundTruthAGM, StreetViewGPS  (CSV)
MAV Images Calib/                   30 checkerboard images
calibration_data.npz                intrinsic matrix + distortion coefficients
readme.txt, loadGroundTruthAGL.m, plotPath.m, write_ros_bag.py
```

`--agz-range FIRST LAST` extracts a different slice of the 81,169-frame flight.

**Caveats.**

- **`Log Files/OnboardGPS.csv` stores latitude and longitude in degrees and altitude in metres** —
  not the 1e7-degree and millimetre units that `readme.txt` describes. Code reading the CSV must not
  apply those scale factors.
- The GoPro has a rolling shutter and strong lens distortion: use `--calib` with `calibration_data.npz`,
  or `--camera-lens fisheye`.
- The GPS is consumer grade, with about 9 m horizontal error.
- `GroundTruthAGL.csv` holds Pix4D-refined poses every 30th image. They are not an independent survey;
  use the swisstopo data below for accuracy.

```
https://data.geo.admin.ch/ch.swisstopo.swissbuildings3d_3_0/swissbuildings3d_3_0_2019_1091-23/swissbuildings3d_3_0_2019_1091-23_2056_5728.citygml.zip

https://data.geo.admin.ch/ch.swisstopo.swissimage-dop10/swissimage-dop10_2019_2683-1248/swissimage-dop10_2019_2683-1248_0.1_2056.tif
https://data.geo.admin.ch/ch.swisstopo.swissimage-dop10/swissimage-dop10_2019_2683-1249/swissimage-dop10_2019_2683-1249_0.1_2056.tif
```

- **Licence:** swisstopo [terms of use for free geodata](https://www.swisstopo.admin.ch/en/terms-of-use-free-geodata-and-geoservices)
  — use, redistribution and commercial use are allowed, **attribution is mandatory**:
  *"Source: Federal Office of Topography swisstopo (swissBUILDINGS3D 3.0 Beta 2019, swissSURFACE3D 2018,
  SWISSIMAGE 10 cm 2019)"*.

**Coordinate caveats.**

- Everything is in **LV95 (EPSG:2056)** with **LN02 heights (EPSG:5728)**.
- **The LAS files carry no CRS metadata.** Assign `EPSG:2056+5728` explicitly in any tool.
- At this site, WGS84 ellipsoidal height is **LN02 + 47.227 m**. EGM96 height is LN02 − 0.111 m, so
  the AGZ log altitudes (above sea level) agree with LN02 to within a few decimetres.
- Time gap: the flight predates 2017, the LiDAR is from 2018, the buildings from 2019. Building facades
  in swissBUILDINGS3D are derived from roofs and footprints (±30–50 cm), and airborne LiDAR barely samples
  walls — allow 0.3–0.5 m tolerance for facade checks.

## Regenerating derived data

Run these from `sih3d_pipeline/` after downloading the inputs above.

### Simulated video input

SIH26158 input is video plus telemetry, but most open datasets ship photos. These rebuild that input.

**Aukerman photos → video + DJI-style `.SRT`** (0.5 s per photo, 30 fps):

```bash
.venv/bin/python scripts/images_to_video.py \
  --images data/odm_aukerman_baseline/odm_data_aukerman-master/images \
  --out data/simulated/aukerman_pass.mp4
```

**AGZ frames → 30 fps video.** Frame *n* of the video must be image `59001 + n`, because the pipeline
maps video frames back to AGZ image ids:

```bash
mkdir -p data/simulated
ffmpeg -framerate 30 -start_number 59001 -i "data/agz_zurich_seg59001/MAV Images/%d.jpg" \
  -frames:v 3000 -c:v libx264 -preset slow -crf 16 -pix_fmt yuv420p \
  data/simulated/agz_zurich_seg59001.mp4
```

This gives the same 3,000 frames, 30 fps and 100 s duration as the original, with frame *n* matching
image 59001+*n* throughout. The original's encoder settings were not recorded, so the bitrate will
differ; `-crf` trades file size against compression artefacts.

**AGZ `.SRT`** — only needed to test the plain-`.SRT` input path. With `--telemetry "data/agz_zurich_seg59001/Log Files"`
the pipeline reads the logs directly and needs no `.SRT`. This reproduces the original file byte for byte:

```python
import csv
from pathlib import Path

# OnboardGPS.csv stores degrees and metres directly (not the 1e7-degree / millimetre units its readme lists)
first, last, fps = 59001, 62000, 30
rows = {}
with open("data/agz_zurich_seg59001/Log Files/OnboardGPS.csv", newline="") as f:
    for r in csv.DictReader(f):
        r = {k.strip().lower(): (v or "").strip() for k, v in r.items() if k}
        imgid = int(float(r["imgid"]))
        if first <= imgid <= last:
            rows[imgid] = r


def stamp(seconds):
    ms = int(round(seconds * 1000))
    h, ms = divmod(ms, 3_600_000)
    m, ms = divmod(ms, 60_000)
    s, ms = divmod(ms, 1000)
    return f"{h:02d}:{m:02d}:{s:02d},{ms:03d}"


blocks = []
for k, imgid in enumerate(range(first, last + 1)):
    r = rows[imgid]
    blocks.append(f"{k + 1}\n{stamp(k / fps)} --> {stamp((k + 1) / fps)}\n"
                  f"FrameCnt: {k + 1}, imgid: {imgid}\n"
                  f"[latitude: {float(r['lat']):.7f}] [longitude: {float(r['lon']):.7f}] "
                  f"[abs_alt: {float(r['alt']):.3f}]\n")
out = Path("data/simulated/agz_zurich_seg59001.SRT")
out.parent.mkdir(parents=True, exist_ok=True)
out.write_text("\n".join(blocks))
print(f"wrote {out} ({len(blocks)} entries)")
```

Save it as a file and run it with `.venv/bin/python` from this folder.

### Prepared keyframes — `data/processed/<name>/`

`scripts/prepare_dataset.py` crops black bars, detects hard cuts, keeps the sharpest frame per ~10%
image shift, drops blurry frames, and writes GPS into EXIF plus `geo.txt` and `gps_priors.txt`.

```bash
PY=.venv/bin/python

# photo sequences with EXIF GPS
$PY scripts/prepare_dataset.py images --images data/odm_aukerman_baseline/odm_data_aukerman-master/images \
    --out data/processed/aukerman
$PY scripts/prepare_dataset.py images --images data/odm_aukerman_baseline/odm_data_aukerman-master/images \
    --strip longest --out data/processed/aukerman_single_strip
$PY scripts/prepare_dataset.py images --images data/semcitylocked/original_images \
    --out data/processed/semcitylocked

# photos whose GPS lives in a CSV
$PY scripts/prepare_dataset.py images --images data/uavscenes_amtown03/interval5_AMtown03/interval5_CAM \
    --gps-csv data/uavscenes_amtown03/interval5_AMtown03/rtk_positions_raw.csv --match time --focal35 21.6 \
    --out data/processed/uavscenes_amtown03

# video + telemetry (the real SIH26158 input shape)
$PY scripts/prepare_dataset.py video --video data/simulated/aukerman_pass.mp4 \
    --telemetry data/simulated/aukerman_pass.SRT --cut-ratio 0 --out data/processed/aukerman_video
$PY scripts/prepare_dataset.py video --video data/simulated/agz_zurich_seg59001.mp4 \
    --telemetry data/simulated/agz_zurich_seg59001.SRT --out data/processed/agz_zurich_video
```

`--cut-ratio 0` disables cut detection, which a slideshow video would otherwise trigger at every
photo change.

### Reconstructions, reports and the viewer

**The full pipeline** writes `data/runs/<name>/report.json` and `data/odm_projects/<name>/`, and
exports the viewer's `viewer/data/<name>/` and `viewer/models.json`. For example, Zurich with
calibration and ground truth:

```bash
.venv/bin/python -m sih3d run --video data/simulated/agz_zurich_seg59001.mp4 \
    --telemetry "data/agz_zurich_seg59001/Log Files" --agz-range 59001 62000 \
    --calib data/agz_zurich_seg59001/calibration_data.npz --rolling-shutter --name agz \
    --lidar data/ground_truth/zurich/2683_1248.las data/ground_truth/zurich/2683_1249.las \
    --citygml data/ground_truth/zurich/swissbuildings3d_3_0_2019_1091-23_2056_5728.citygml.zip
```

**OpenDroneMap directly**, on a prepared image set:

```bash
mkdir -p data/odm_projects/aukerman
cp -al data/processed/aukerman/images data/odm_projects/aukerman/images   # hard links, no copy
scripts/run_odm.sh aukerman                                              # extra ODM flags may follow
```

**Accuracy outputs** in `data/results/`:

```bash
# Aukerman: building dimensions vs the OpenStreetMap outline
.venv/bin/python scripts/measure_building.py \
    --cloud data/odm_projects/aukerman/odm_georeferencing/odm_georeferenced_model.laz \
    --reference data/ground_truth/aukerman_osm_buildings.json --way 749959908 --out data/results/aukerman

# SemCityLockeD: buildings vs official LoD2 models (scale is never fitted)
.venv/bin/python scripts/compare_lod.py \
    --cloud data/odm_projects/semcity/odm_georeferencing/odm_georeferenced_model.laz \
    --roof data/semcitylocked/LoD_model/semantic_obj/TUM_CC_lod2_RoofSurface.obj \
    --ground data/semcitylocked/LoD_model/semantic_obj/TUM_CC_lod2_GroundSurface.obj \
    --out data/results/semcity
```
